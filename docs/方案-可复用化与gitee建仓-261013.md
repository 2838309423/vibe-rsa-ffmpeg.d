# 方案：把这套「口播音频 + 插图 → 成片」流程做成可多次复用的仓，并给它一个 gitee 仓库

> 甲方 2026-10-13 交代：「你给该方案推荐一个 gitee 仓库。这是一个可以多次使用的视频创作方案，不是单独只做这一个视频的。」
> 本文只记录**建议与待办**，动手与否等甲方点头。

## 一、推荐仓库名（含探测读数）

**主推：`git@gitee.com:gushiteng/vibe-rsa-ffmpeg.d.git`**

依据两条实测：

1. 本机 gitee 仓名与工作区文件夹名**一一相同**（`.d` 后缀保留）：
   实测 `~/m4a-asr-to-chinese.d/.git` 的 origin = `git@gitee.com:gushiteng/m4a-asr-to-chinese.d.git`
   （注意：把 `.d` 去掉后的 `m4a-asr-to-chinese.git` 是 404，说明甲方的仓名就带 `.d`）。
2. 候选名探测（`git ls-remote`，404=可占用）：
   `vibe-rsa-ffmpeg.d`、`vibe-rsa-ffmpeg`、`vibe-rsa-video-pipeline.d`、`vibe-rsa-doubao-recut.d` **全部为 404 ⇒ 都还没被占用**。

按 `m4a-asr-to-chinese.d` / `vpsdsh-shortstory-workspace-wrapper.d` 的既有命名习惯，**带 `.d`、与工作区同名**最省事：
现有工作区 `/home/longxia/vibe-rsa-ffmpeg.d` 直接就是仓根，不用搬家、不用改远端名。

备选命名（要更能自解释时才用）：

| 候选 | 适用场景 |
|---|---|
| `vibe-rsa-ffmpeg.d` | **主推**，与工作区同名、与既有仓同一风格 |
| `vibe-rsa-ffmpeg` | 想在 gitee 上去掉 `.d`（但会与本地文件夹名不一致） |
| `vibe-rsa-video-pipeline.d` | 想让人一眼看出是「流水线/可复用工具」 |
| `vibe-rsa-doubao-recut.d` | 想强调输入形态（豆包朗读音频 + 插图重剪） |

> 另有一条硬约束：**我建不了 gitee 仓**。SSH 只能推已存在的仓（`m4a-asr-to-chinese.d` 的 `git push --dry-run` 干净通过，
> 但新建仓要 gitee OpenAPI token，我没有）。所以要么甲方给 token（我调 API 建），要么甲方在网页上建空仓（我随后推）。

## 二、可复用性体检（现状：好用但绑死了这一个片子）

| 位置 | 现状 | 复用障碍 |
|---|---|---|
| `bin/build_plan.py` | 15 张图 + 文稿片段写死在 `SEGMENTS` 列表里 | **换片子就得改代码**，最该外置的一项 |
| `bin/build_plan.py` / `bin/render_video.sh` | `FPS = 30` 写死 | 换帧率要改两处 |
| `bin/prep_frames.py` / `bin/render_video.sh` / `bin/verify_video.py` | `886x1920` 写死（verify 还断言它） | 换画幅要改三处 |
| `bin/*.py`、`bin/*.sh` | ffmpeg 路径写死 `/home/longxia/toolchain/...` | 换机器/换用户就断 |
| `bin/asr_cn.py` | 业务空间域名从 `~/.config/aliyun-bailian/api-key.txt` 推导（这个设计是对的，保留） | — |
| `.gitignore` | 排除了 `*.jpg` | 示例图/对账图进不了仓 |
| `work/` | 混放「输入件」与「中间产物」，且整体被 gitignore | `doc.txt`、`segments.json`、`images/` 是**复用价值最高**的样例，却进不了仓 |

`work/` 体积分布（清理可省 60+ MB）：`frames/` 21M、`segfr/` 17M、`render/` 15M、`diff/` 5.2M、`audio16k.wav` 5.1M。
